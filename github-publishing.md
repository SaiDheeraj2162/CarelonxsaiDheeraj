# GitHub Publishing Guide

## Before the first push

1. Review the included MIT [LICENSE](../LICENSE) with the legal owner and replace it if your organization requires another license. Read [NOTICE.md](../NOTICE.md): the source-code license does not grant rights to use Carelon trademarks or brand assets.
2. Create the GitHub repository without an autogenerated README, `.gitignore`, or license so the local history remains the source of truth.
3. Review every fixture and confirm it is synthetic. Do not publish credentials, API keys, real operational data, or confidential solution material that you are not authorized to share.

## Push and enable Pages

```sh
git add .
git commit -m "Initial Complete-First prototype"
git remote add origin https://github.com/OWNER/REPOSITORY.git
git push -u origin main
```

In the repository, open **Settings → Pages** and select **GitHub Actions** as the source. The [Pages workflow](../.github/workflows/pages.yml) builds `dist/` and publishes it after verification succeeds.

## Recommended repository settings

- Protect `main`: require pull requests, passing **Verify prototype** checks, and conversation resolution before merge.
- Enable Dependabot alerts and GitHub Actions Dependabot updates.
- Enable private vulnerability reporting if the repository visibility and plan support it.
- Enable Discussions if you want a separate place for usage questions.
- Review Actions permissions at the organization level; the included workflows use least-privilege job permissions.

## Intentional omissions

`CODEOWNERS` and `FUNDING.yml` are not included because their values depend on the real GitHub organization, team, and funding destination. Add them only after those details are known. The repository is intentionally `private` in `package.json` to prevent accidental npm publication; this does not affect GitHub Pages.
