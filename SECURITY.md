# Security Policy

## Supported version

Security fixes are applied to the current `main` branch of this prototype.

## Reporting a vulnerability

Do not file a public issue for a suspected vulnerability or exposure of sensitive data.

After this repository is published, use GitHub's **Report a vulnerability** control on the repository's **Security** tab when Private Vulnerability Reporting is enabled. If that control is unavailable, contact a repository maintainer privately and include:

- a concise description of the issue;
- the affected file or workflow;
- safe, reproducible steps; and
- potential impact and any suggested mitigation.

Please do not include real member, provider, clinical, credential, or secret data in a report. Maintainers will acknowledge a valid report, assess it, and coordinate a remediation path before public disclosure.

## Prototype boundary

This repository intentionally contains synthetic fixtures only. If you find real data, an exposed credential, a vulnerable GitHub Action configuration, or a cross-site scripting risk in the static app, treat it as a security report.
